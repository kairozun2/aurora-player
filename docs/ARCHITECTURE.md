# Архитектура Aurora Player

## Два слоя

```text
            +--------------------------------------------+
  QML  -->  |  app/ : PlayerBridge, 4 модели, провайдер  |
            |         обложек, JSON-переводчик            |
            +---------------------+----------------------+
                                  | обычные C++ вызовы
            +---------------------v----------------------+
            |  core/ : Controller — единая точка входа   |
            +--------------------------------------------+
            | AudioEngine | MediaLibrary | Downloader    |
            | Decoder     | TagReader    | Config        |
            | Equalizer   | Lyrics       | I18n          |
            +--------------------------------------------+
```

`core/` не знает про Qt вообще: только STL. Поэтому его можно собрать и протестировать
на любой машине с компилятором C++17, встроить в другой интерфейс или в серверный сервис.
`app/` не содержит ни одной строчки звуковой логики — только показ данных.

## Поток звука

```text
файл / URL
   |
   v
Decoder (WAV напрямую | ffmpeg через pipe -> f32le 48000 Hz stereo)
   |
   v
поток декодирования  --push-->  RingBuffer (32768 кадров, lock-free)
                                     |
                        аудио-колбэк  v
                     Equalizer (10 биквадов на канал)
                                     |
                                     v
                        громкость, скорость, кроссфейд
                                     |
                                     v
                   ISink: QtAudioSink | WavFileSink | NullSink
```

Правила, которые держат звук стабильным:

1. В аудио-колбэке нет `new`, `malloc`, мьютексов, логов и системных вызовов.
2. Кольцевой буфер — один писатель, один читатель, только атомарные индексы.
3. Перед стартом буфер набирает данные (`priming`), поэтому первые кадры не пустые.
4. Все параметры (громкость, эквалайзер, скорость) читаются атомарно и сглаживаются,
   чтобы не было щелчков.
5. Offline-приёмники (рендер в WAV) работают синхронно: движок ждёт, пока данные
   действительно уйдут в файл — иначе в файл попадала бы тишина.

## Gapless и кроссфейд

Движок держит два потока декодирования: текущий и предзагруженный. Когда до конца трека
остаётся меньше, чем длина кроссфейда, второй поток уже открыт и заполнен. При gapless
без кроссфейда буферы просто стыкуются, при кроссфейде складываются с косинусной кривой.
Следующий трек движок спрашивает у `PlayQueue` через callback-провайдер, поэтому очередь,
повтор и перемешивание работают и во время перехода.

## Фонотека

- `MediaLibrary::scan(roots, incremental)` идёт по папкам, сравнивает размер и `mtime`,
  и трогает только изменившиеся файлы.
- Индекс — обычный JSON (свой парсер в `core/src/Json.cpp`), лежит в data-каталоге.
- Поиск нормализует регистр, убирает диакритику и **транслитерирует кириллицу**,
  поэтому `polyarnaya` находит «Полярная», а `veter` — «Северный ветер».
- Теги читаются вручную: ID3v1, ID3v2.2/2.3/2.4 (включая UTF-16 и unsynchronisation),
  Vorbis comments для FLAC и OGG, атомы `ilst` для MP4. Если тегов нет, имя файла
  разбирается по шаблонам вида `01 - Artist - Title`.
- `ffprobe` используется как резервный источник длительности и битрейта.

## Загрузки

`Downloader` — пул рабочих потоков. Ссылка классифицируется: прямой аудиофайл качается
сам, страница YouTube и прочих сайтов отдаётся `yt-dlp`, чей вывод парсится построчно для
прогресса, скорости и ETA. Готовый файл сразу попадает в фонотеку с тегами и обложкой.
Отмена закрывает процесс и удаляет частичный файл.

## Локализация

- Строки ядра проходят через `aurora::tr(key)` со словарями в `core/src/I18n.cpp`.
- Строки интерфейса — обычные `qsTr()`, но вместо `.qm` файлов используется
  `QmlTranslator`: он читает плоский JSON (`i18n/ru.json`) и отдаёт перевод по исходной
  строке. Благодаря `QQmlEngine::retranslate()` язык меняется мгновенно, без перезапуска,
  и добавить новый язык может любой человек без установки Qt Linguist.

## Тесты

`tests/test_core.cpp` — 308 проверок без внешних фреймворков: кольцевой буфер, JSON,
строки и транслит, WAV round-trip, эквалайзер, движок (включая счётчик underruns),
теги, `.lrc`, фонотека, плейлисты, конфиг, анализ волны и палитры, контроллер.
Запуск: `ctest --test-dir build --output-on-failure` или `make test`.
